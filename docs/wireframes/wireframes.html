Chinchilla Capture — Wireframes v0.2

Screen region capture → floating prompt panel → multi-turn, tool-using vision agent. Linux, Wayland-first, GNOME.

Target: Ubuntu 24.04 / GNOME 46 on Wayland Toolkit: Python 3 + GTK3 (PyGObject) Hotkey: Ctrl + Alt + A Status: pre-code design review
v0.2 adds: persisted sessions · multi-capture threads · OpenAI / Anthropic / OpenRouter / custom providers · editable action titles & prompts · web search with citations
00

Flow at a glance

the whole product in six beats

One shortcut. Drag a box. Keep talking.

A resident, terminal-less process owns a global hotkey. It paints a fullscreen selection layer, grabs the pixels you framed, and instantly opens a frameless always-on-top panel with the crop attached to a persisted session. Three editable one-click actions plus a free-text box, follow-up turns, extra captures dropped into the same conversation, and optional web search. No paste, no file dialog, no browser tab.

STEP 1

Hotkey fires

Ctrl Alt A — registered with the compositor, no terminal window ever appears.

STEP 2

Selection layer

Whole desktop dims, crosshair follows the pointer, drag to frame. Live W × H badge and magnifier.

STEP 3

Panel joins a session

Crop goes into the active session, or a brand-new one. Every turn is written to a file as it happens.

STEP 4

Keep the thread going

Follow-up prompts reuse the crops already in the session. CtrlR adds another capture to the same conversation.

STEP 5

Search the web when it matters

A toggle gives the agent a real Google search tool over your local Chrome; answers come back with [1] citations and a source list.

STEP 6

Any provider

OpenAI, Anthropic, OpenRouter, or a custom OpenAI-compatible endpoint from .env. Same panel, same chat() contract.

Never a terminal — single instance, tray icon Never a copy-paste — pixels go straight into the session Keyboard first — 1/2/3 choose an action, Enter sends Survives restart — the thread is a file, not RAM
Constraint — Wayland has no global hooks

The shortcut is a GNOME custom shortcut bound to chinchilla capture; pixels come from the portal Screenshot API (one consent prompt, then silent).

Constraint — always-on-top under GNOME

Frameless panels need gtk-layer-shell (or a hint + transient-for) to float above other windows. X11 fallback is override-redirect.

Decision — the session is the unit

One JSON file per session holds title, ordered turns, capture references and sources. The panel is just a view of that file, reloaded on start.

Decision — one agent, one tool belt

Providers sit behind one adapter. Web search is an MCP stdio server (dsh-google-chrome-search) exposed to the model as tools, not a bespoke API.

Session & turn, not a single call

No stored keys in the repo.env is read for the custom provider only; the file is in .gitignore and the UI never shows the value, only a masked field and a status.

What the model actually sees

toolsonly when the toggle is on and the provider supports function calling
budgetmax 4 tool calls / 20s, then it must answer with what it has
citationsevery fetched URL is numbered; the renderer turns [n] into chips

Tool loop — bounded on purpose

planthe model decides: answer from the image, or search first
searchone query, up to 8 organic results, snippets trimmed to 800 chars
fetchtop 1-2 pages, readable text capped at 6k chars each
stop4 calls, 20s wall clock, or the user presses Stop — then it answers

Rendering rules

chipsa [n] with no matching result is scrubbed before paint
sourcesdeduped by URL per session; title + domain, hover shows the query
footerSources reopens the list after the answer scrolls away
Tool activity is visibleEach call shows its name, its argument and its duration while running, so a slow search never looks like a hung panel.
Citations are computed, not inventedThe sources list is built from the tool results; a [3] that no tool produced is scrubbed before rendering.
No search, no lieIf the MCP server is missing the panel shows one inline line: "web search unavailable — answering from the image only".
Cost guardWeb turns run on the session provider but are capped harder: search snippets are trimmed to 800 chars, page fetches to 6k.

Element spec

  1. 1
    Session header — capture stack (46×32 + count badge), editable title that opens the session selector, × closes (Esc).
  2. 2
    Tool row — web-search switch, + Capture, + Session. 23px pills; state persists per session and is mirrored in the footer while running.
  3. 3
    Action row — three equal cells, 7px gap. Labels come from settings; active action keeps a 1px colored ring. Keycaps are hints, not widgets.
  4. 4
    Free prompt — 34px tall, always visible, focused on open. Enter sends; follows the thread, not just the last capture.
  5. 5
    Thread + footer — turns scroll up to 70% of screen height; tool activity and citations live inside the assistant bubble. Footer: provider, model, tokens, Stop / Copy / Retry.
hotkey→ portal grab→ crop→ append to session→ agent ± tools→ panel

Build order — each step is demoable on its own

1Overlay + fake crop. Draw and commit a box over a hardcoded image.
2Real capture. Portal screenshot, DPI-correct crop, PNG in memory.
3Panel + thread, canned. Layout, focus order, keys 1/2/3 offline.
4Session files. Create, append, reload, list, delete. Restart never loses a thread.
5Providers + streaming. OpenAI/Anthropic/OpenRouter/custom behind one adapter.
6Editable actions + settings. Titles, prompts, keyring, retention.
7Web search. MCP client, tool loop, citations, no-search fallback.
8Shortcut install + autostart. The last mile that makes it feel native.

Request shape — one agent turn

messagessystem directive + every turn of the session, oldest first
capturesimage block per crop in the thread; older ones at detail: low
toolssearch / fetch / search_and_fetch / account — only when the toggle is on
replystreamed text + tool events; [n] resolved against real result URLs
Single processOne Python daemon owns the tray, overlay, panels and the MCP subprocess child. One panel per session, reused if open.
DPI awareCoordinates kept in logical px for drawing, converted to device px only for cropping the raw frame.
Latency budget~40ms portal grab, <60ms overlay paint, first token <1.5s; a web turn adds ~4-6s of tool time, shown per call.
Failure pathNo key, no network, 429, missing MCP server — all inline cards with the fix next to them, never a dialog.
